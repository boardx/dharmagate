# Dharmagate 产品定义

版本 v0.1 · 设计提案 · 2026-10-25

配套：[产品定义](product-definition.zh-CN.md) · [架构定义](architecture-definition.zh-CN.md) · [UIUX 设计](uiux-design.zh-CN.md) · [完整 backlog](backlog.md)

## 01 产品定义与决策摘要

**产品定位：全球佛学联合目录与可信学习服务。** Dharmagate 连接散落的经典、译本、注疏、研究和讲授资料，对有明确许可的内容提供保存、检索与下载，对不能复制的资源保留允许的书目与原站入口。AI 帮助人理解、比较和反思，但不替代师者、不评定觉悟。

本文件面向发起人、产品、内容与合作团队，定义‘为谁解决什么问题、首发做什么、怎样判断完成’。配套《架构定义》回答技术实现和运营边界，《UIUX 用户体验设计》定义页面、交互与状态；三者共享术语、约束和 DG 编号 backlog。

| 决策 | 本版基线 |
| --- | --- |
| 首发闭环 | 一条经核许可的来源，10 至 30 部代表资料，走通采集到引用回答、阅读书签和纠错。 |
| 范围顺序 | P0 可信文本闭环；P1 按需求扩 OCR、影音或教学；P2 经论证后立项。 |
| 影音约束 | 不使用 Cloudflare Stream；R2 加自有播放器，必要转码由已核准计算资源负责。 |
| 成功标准 | 可靠出处、权限正确、用户完成任务与自主选择；不以文件总数或使用时长代替觉悟。 |

**状态：设计提案，不是功能完成声明。** 全部 backlog 为 proposed_pending_baseline，先与现站成果对账再估算；不默认已开工、获权或验收。旧站保持独立稳定，新旧路由、绑定与数据保护为 P0 前提。发布文档不等于授权批量下载、生产变更、购买服务或创建外部 issues。

‘全球最全’是长期愿景，不能宣称现已实现。第一期是否扩大规模，由权利、质量、人员和成本门槛共同决定。

## 02 全球覆盖与权利分层

### 把规模目标变成可以核查的清单

以作品为知识单位，以版本、语言表达、出版载体和数字文件为不同实体。既收经典与论疏，也记录注释、学术研究、当代讲授与实践资源；不同类别必须清楚标示，不把现代讲义自动标为经典。总体覆盖矩阵先以汉语、巴利语及英语为候选；首个闭环只取其中一条经核许可的小型来源，藏语、梵语、日语等分阶段加入，并邀请对应语言与传统的专家校核。

覆盖报告同时公布：已知来源数、已登记作品与版本数、已获完整权利资料数、全文可检索率、可下载率、影音转写覆盖率、链接存活率与待确认规模。避免用文件数或切片数包装‘全世界资料数’。重复扫描不等于新增作品，完整的不同译本也不应被去重消失。

| 层级 | 服务方式 | 入库条件 |
| --- | --- | --- |
| 联合目录 | 书目、摘要、馆藏与原站链接 | 确认元数据可用范围；不得把抓取全文当目录收录。 |
| 开放内容库 | 全文、扫描、音视频与合法下载 | 逐项证明适用的公版地位或许可；履行署名及其他义务。 |
| 合作授权库 | 按身份、地区、用途与期限访问 | 书面合作，明确复制、衍生、AI、分发、撤回与费用。 |
| 受限资源目录 | 只展示允许的描述与申请入口 | 不绕过登录、付费、密传或机构限制；不生成内容替代品。 |
| 未知或争议 | 隔离，不公开内容或投入 AI | 指定责任人补证；取得结论后才能进入下一阶段。 |

### 按用途分别记录权限

记录 metadata_index、preserve_original、public_display、download、translate、OCR_ASR、embeddings、RAG_quote、model_training、redistribution、commercial 等独立用途，分别使用 allowed、denied、conditional 或 unknown。公开可读不等于允许再分发；古代原文公版不代表现代译本、校勘、扫描图像或录像也公版。非商业许可需要结合实际收费、赞助与运营模式审查，禁止改编条款也不能简单推定允许转写和机器翻译。

发布前保留许可原文快照、网址、获取日期、版本及权利人联系信息；设到期提醒和撤回流程。涉及司法辖区、公版计算、数据库权或合同解释时，由专业法律人员和合作机构核定，不由语言模型自行裁决。

CC 条款未明确提及 AI，并不自动意味着一律允许或一律禁止；应结合许可全文、具体用途、合同与适用地区审查。第一期关闭模型训练，只有经过单独确认的语料才考虑后续训练。免费页面也不当然消除非商业条款对整体项目运营的影响。

以下是候选来源，不是已获得完整镜像授权的名单。按每个集合与作品核验，不能把同一机构旗下所有数据套用一个许可；元数据本身也可能有批量复用条件。建议先从许可清楚、机器可读、版本结构稳定的集合建立小规模样板。

| 来源 | 优先价值 | 首期处理与权利门槛 |
| --- | --- | --- |
| SuttaCentral Bilara | 巴利经典与多语对照 | 优先核验并接入支持创建且明确 CC0 的文本。Bilara 支持创建的译文许可不能泛化到全站第三方资源。[B1] |
| CBETA | 汉文典籍及结构化标记 | 默认 CC BY NC SA 4.0；印顺、吕澂、太虚、演培相关资料另有例外。逐集合审批，不能据默认许可全量复制。[B2] |
| SAT | 大正藏检索及图像参照 | 主库学术与非营利用途、禁止再分发；图像库及嘉兴藏规则不同。先目录和链接，授权后再复制指定集合。[B3] |
| BDRC | 藏文与相关传统书目和扫描 | 优先联合目录及馆藏关联。平台不拥有底本版权，开放下载不是通用转授权；逐项查访问政策和权利状态。[B4] |

| 其他研究与馆藏库 | 梵文、日文、敦煌与手稿 | 按机构白名单逐个研究；先登记稳定标识符和馆藏来源，未确认的全文不下载、不训练。 |

### 首批来源选择规则

选择 3 至 5 个来源先验证合作流程、文本质量和引用定位，而不是一次开启全球抓取。每个来源指定数据负责人及学术校核人，检查版本更新、字段语义、字符编码、撤回机制和归属信息。若上游提供正式数据包或接口，优先于网页抓取；保留上游 ID，方便增量同步与双向纠错。

对不可镜像的资源，优秀的联合目录仍能提供价值：用标准化题名、异名、译者、典籍编号与来源链接，把分散藏品连起来，并清楚告知为何只能跳转原站。不要以限制为由绕开来源机构，更不要把无法下载的文本从全球覆盖报告中抹掉。

| 来源 | 可利用内容 | 首期动作与边界 |

### 同作品不同版本必须分别登记

SARIT 与 GRETIL 的《佛所行赞》示例说明，古典作品相同，不等于数字版本许可相同。原始录入、底本、校勘和格式转换形成的来源链，都应出现在 provenance 中。BDRC 的本体可以借鉴作品、版本、人物与地名模型，但其本体 CC0 不等于全部扫描或元数据也是 CC0。[B7][B8][B13]

敦煌和其他手稿的数字图像需看每一件标明的公版、开放许可或第三方权利。不得从馆方‘开放访问’宣传语推断整馆影像可镜像；对韩国 ABC 等尚未完成官方条款核查的来源，本版只列研究线索。[B14]

## 05 用户价值与功能边界

产品面向不同经验与目标的人，不假定所有人都信奉同一传统。默认可匿名查阅公开资料，用户可以只找书、只看原文，也可以选择学习或联系真人。宗教倾向、困扰与日记不是进入资料馆的必填条件。

| 主要用户 | 核心问题 | 可验证的产品价值 |
| --- | --- | --- |
| 普通学习者 | 不知道可信资料在哪里，容易被无出处解释误导 | 找到可理解解释与原文，分清 AI 释义和来源观点。 |
| 师者与法师 | 希望提供正确上下文并保护传承边界 | 审阅本机构内容、回应纠错，明确不宜开放的范围。 |
| 研究者 | 作品、版本和语言散落在不同库 | 按编号找书、比较译本、追踪版本与精确引用。 |
| 教师与带领者 | 需要组织适合课程的阅读与讨论 | 建立获准资料清单，查看自愿提交的学习反馈。 |
| 机构与馆藏方 | 希望扩大可见性，又保有出处和控制权 | 管理授权、获得流量回流、纠错并执行撤回。 |

### 首发功能范围

公开联合目录、合法全文阅读、精确与语义搜索、可点击出处的问答、版本信息、私人书签、内容纠错、权利与采集后台，是首个闭环。AI 回答之外必须保留直接检索与阅读路径；即使模型不可用，资料馆仍能工作。

### 明确不纳入首发

不承诺全球全量下载，不处理未授权现代书籍和影音，不训练专用基础模型，不复制师者声纹，不做证悟判定，不建设完整社交、直播、支付或捐赠系统。巨型知识图谱、全部语种、实时语音导师、复杂推荐画像都不能成为首发前置。

### 内容与增长原则

来源质量与权利可证明性优先于数量；用户任务成功优先于停留时长；多传统语境优先于统一解释；真人支持优先于对 AI 的情感依赖。商业或公益模式须先确定，它会影响非商业许可资料能否进入对应产品区域。

## 06 面向人的四层体验

数据库搜索不等于觉悟。产品要支持人的自主理解与实践，而不能把修学变成模型给分或平台增长。建议分为资料层、理解层、修学层和真人关系层，允许用户只使用其中一层，不强制填写信仰、情绪或个人经历。

| 层次 | 主要体验 | 明确不做什么 |
| --- | --- | --- |
| 资料层 | 找经典 查版本 观看或下载合法资料 | 不以流量排名替代来源可靠性。 |
| 理解层 | 解释术语 比较译法 展示不同传统观点 | 不声称生成答案就是佛陀或师者的原话。 |
| 修学层 | 用户自选短时练习 读书计划 自省记录 | 不评定开悟等级，不用连续打卡羞辱用户。 |
| 真人关系层 | 经核验的机构 师者与学习社群入口 | 不把 AI 塑造成精神领袖或替代现实关系。 |

### 新手旅程

一个第一次接触佛学的人，可以从具体问题进入：例如想理解‘无常’，先收到清楚标注传统与来源的短解释，再看到可读原典和一项可自由跳过的简短观察练习。系统询问是否愿意继续，而不是立即索取心理画像或开启长期修学计划。用户可以说不认同、换传统、只看原文或停止。

### 有经验者与研究者旅程

已有修学经验的人可选择熟悉传统与经论，建立私人书架、并排阅读注疏，查看不同传承对同一概念的解释；研究者可追踪版本、下载许可清楚的资料、引用精确定位、导出书目与差异。推荐必须提供理由，并允许按年代、版本与来源排序，不能只依赖相似兴趣过滤。

### 师者和机构旅程

教师可以在授权范围内组织课程与资料清单，审阅本机构内容并回应纠错；平台提供来源控制和学习者自选联系渠道。教师不能默认读取私人日记或所有 AI 对话。课程报名、付费、认证和未成年人参与若纳入产品，须单独建立知情同意与管理规则。

衡量体验以‘是否找到可信资料、是否理解出处与差异、是否保有自主选择、是否顺利联系真人’为主。每日时长、黏性、打卡天数和模型赞同率可以作为运营观察，但不能被称为觉悟指标，也不应成为推荐系统的主要优化目标。

## 07 师者治理与安全边界

### 治理要能处理分歧而不是消除分歧

建立由不同传统、语种、学术背景与实践经验组成的审阅网络，公开成员角色、选择方式和利益冲突。机构验证、学术审阅与修学资质是不同标签；不要用单一‘认证大师’标识替代复杂的传承和责任关系。用户应知道一段内容由谁提供、谁校核、是否属于某一传统的解释。

| 职能 | 责任与权限 |
| --- | --- |
| 数据与权利负责人 | 批准来源范围、许可证据和撤回；对未确认材料有停止发布权。 |
| 语言与经典审阅者 | 校核专名、译本、引用和版本关系；记录异议，不覆盖原始证据。 |
| 师者与实践顾问 | 审阅面向修学的表述和风险；不得访问未授权的个人记录。 |
| 信任安全团队 | 处理误导、骚扰、冒名、危险实践及敏感人群问题。 |
| 工程与安全负责人 | 执行权限、审计、备份、恢复、删除和模型发布门槛。 |
| 独立申诉渠道 | 接受作者、机构和用户申诉；有时限、记录与可纠正的结果。 |

### AI 的角色声明应落到行为

AI 是资料与理解助手，不是佛陀、上师、治疗师或对用户精神成就的裁判。它应区分文本内容、传统观点与个人实践建议；不承诺通过某个练习必然开悟，不把病症、灾难或人生遭遇归咎于用户业障，不煽动断绝现实支持，不鼓励以禁食、睡眠剥夺或疼痛证明修行。

遇到强烈痛苦、失眠、异常感知、自伤风险或明显功能受损的描述，应暂停强化神秘或确定性解释，提供平静、非羞辱性的支持并鼓励联系可信任的人和适当专业帮助；需要紧急支持时使用经核验的本地资源。不要将用户的描述当作证悟、附体或某种疾病的确定证据。

### 有边界的修学辅助

只提供可选择、可停止、低强度的普通学习与自省工具。涉及长时闭关、强烈呼吸练习、身体风险、特殊灌顶或传承限制的内容，应尊重来源限制并指向合适真人指导。儿童与青少年采用更审慎的体验；不采集用于广告或模型训练的宗教与心理画像。

建立答复纠错和模型更新评审流程。发生严重错引、权限泄露或危险建议时，可单独关闭相关功能、回滚模型配置并调查，而无需让整个资料目录下线。

## 08 P0 文本闭环与产品要求

首个端到端闭环：许可登记 → 有界采集 → 原件校验 → 文本规范化 → 版本与片段 → 关键词及语义检索 → 有出处回答 → 原文阅读与私人书签 → 纠错审核。应选择一条资料源和 10 至 30 部可代表主要格式的资料，不用大规模演示掩盖基本链路未通。

| 要求 | 验收行为 | Backlog 关联 |
| --- | --- | --- |
| 旧站不受损 | 新首页继续连接原应用；已登记路由、登录回调和资源路径通过兼容测试。 | DG 001 至 004 |
| 来源可追溯 | 每个公开片段找到原件、来源、版本和许可；unknown 不能发布。 | DG 007 至 015 |
| 搜索可解释 | 用户可以精确找编号、筛选版本、查看命中原段；语义失败不阻塞关键词。 | DG 016 至 018 |

### 角色权限的产品规则

匿名访客只接触公开资料；注册用户可管理自己的私人空间；内容编辑者可处理指定来源；权利审核者决定用途许可；技术管理员不因运维身份自动获得私人日记阅读权限。师者需要用户逐项授权才能查看学习记录，授权可以撤销。

### 异常和退化必须可理解

无结果时解释检索范围并提供替代关键词；只有目录时清楚说明只能跳转；许可撤回时不继续播放旧缓存；AI 不可用时保留原文检索；上传和处理失败时说明状态及下一步。不要用‘AI 正在思考’掩盖权限错误、成本封顶或资料尚未审阅。

### 首个可交付产品的范围

交付联合目录、合法的全文阅读与下载、关键词和语义搜索、带原文证据的问答、基本多版本对照、个人书架和内容纠错。用户不需要注册即可搜索与阅读公开内容。管理员可以管理权利、暂停来源、撤回资源并查看处理失败。

### 首期明确不做

不开展无限制全球抓取，不承诺覆盖所有语种，不把每个来源自动变成镜像，不训练自有基础模型，不建设精神成就评分，不开展需要高风险身体实践的自动指导，不建立未经核验的师者市场。直播、实时语音导师、大规模社区与商业课程体系须另行立项。

工程推进与合作谈判并行，但不能把谈判中的内容提前放进生产。上线仅是受控试运行的开始；之后按月发布覆盖和质量报告，按季度复核权利、成本、语言偏差与治理结构。

## 10 验收 风险与待决策事项

以下是建议的试点验收门槛，需在第 15 天前由产品、工程、学术与权利负责人确认。先固定测试集与计量方法，再评估，避免上线后移动标准。质量指标分别按语种、来源类型和难度报告，不用平均数掩盖小语种失败。

| 维度 | 建议门槛与证据 |
| --- | --- |
| 权利与溯源 | 公开内容 100% 具备来源、许可状态、用途规则及版本；unknown 无法发布。 |
| 精确检索 | 已知典籍编号与标题测试集前 3 结果命中率至少 95%；异名与版本单独统计。 |
| 语义检索 | 由本语专家标注的测试集建立基线；前 10 结果召回目标至少 85%，逐语种验收。 |
| 证据问答 | 人工抽评至少 200 题；关键事实引用正确率目标至少 95%，无证据问题能拒绝编造。 |
| 权限与安全 | 越权读取和受限内容泄露测试必须为 0；提示注入和文件上传攻击有阻断证据。 |
| 撤回与恢复 | 演示一次内容及衍生索引撤回、一次私密数据删除、一次可用的备份恢复。 |
| 体验与无障碍 | 代表性新手、研究者和师者完成核心任务；键盘与字幕检查无阻断缺陷。 |
| 运营与成本 | 真实用量与账单映射、预算告警、降级和回退演练完成；不留无主事故告警。 |

### 最重要的风险

权利误判可导致整个集合下线；过度依赖单一供应商会削弱文化资料的长期保存；低质量 OCR 和跨语误译会把错误放大为可信答案；来源与传统偏差会形成虚假的唯一佛学叙事；AI 与师者身份混淆可能伤害脆弱用户。对应措施分别是用途闸门、可导出与独立备份、分语言评测、来源多元和显式真人治理。

### 建议发起人先确定的六项选择

一是项目的公益与商业边界；二是第一期传统、语种和合作来源；三是首期云与人工预算上限；四是谁对权利、学术和安全分别负责；五是是否需要中国大陆独立部署与合规路径；六是何时批准进入独立测试环境的实施。确认这些即可开始有限试点，无需等待‘全世界数据’齐备。

资料是否可以采集、功能是否可以上线、是否新增付费服务，均以对应的明确授权为准。三份设计文档用于建立共同基线，不把未决定事项自动转成执行指令。
