# DharmaGate 开发 Backlog（建议基线，2026-10-25）

## 范围与状态

- 共 45 项：P0 28 项、P1 11 项、P2 6 项；所有状态为 `proposed_pending_baseline`，表示待与当前站点实际成果对账，不表示已有功能不存在，也不表示已获实施、采购或权限授权。
- 完全排除 Cloudflare Stream。影音使用 R2 + 播放器；必要转码、OCR 和 ASR 经适配器使用已核准的计算资源，不假设全部可在边缘请求中执行。
- 不以“用到所有 Cloudflare 产品”为目标。先交付可信文本闭环，再用真实流量和资料结构决定扩展。
- 尊重多传统与真实师长；支持理解、反思、实践和人类互助；不评价证悟，不设置觉悟分数、业力分数或信仰深浅画像。
- 本计划不创建外部 issues，不默认批量下载，不新增凭据或服务；每项资料操作仍受许可、隐私和现有授权约束。


- P0 即包含最小撤权闭环：权威许可状态提交后，新请求被阻断，旧链接、旧索引和答案缓存不能返回受限内容。P1 DG-038 仅扩展多来源影音的异步规模化清退；不能等待清退完成才停止访问。已被用户合法下载到本地的副本不可被平台技术上追溯撤销。

## 第一条可上线闭环

选定一条有明确权利依据的资料源和 10–30 部代表性资料：

**许可登记 → 有界采集 → 原件校验 → 文本规范化 → 版本和片段 → 关键词/语义检索 → 有出处回答 → 原文阅读/私人书签 → 纠错审核。**

新首页必须继续连接旧应用，原绑定、数据和路由不能因资料馆上线而被替换。P0 的最终出口为 DG-028，不是某一次模型输出或 CI 成功。

主依赖链：DG-005/007/008 → DG-009/010/011 → DG-012/013/014/015 → DG-016/017/018 → DG-019/020/021 → DG-022/023 → DG-028。DG-001–004 的旧站保护、DG-006/026 的身份隐私及 DG-027 的预算保护并行推进，最终汇合验收。

## 估算说明与阶段

以下是粗略主动工程及编辑人日，不是报价或交付日期；先对账并复用旧站恢复、现有身份及已完成测试。合计只反映范围规模，不可直接当成日历工期：

- P0：64–136 人日。
- P1：43–89 人日。
- P2：35–84 人日。

假设有可持续投入的产品负责人、约 3 名跨前后端/数据/AI 工程师、设计支持、内容与许可负责人及兼职多传统顾问；缺少相应角色或语料授权时不得据此承诺 90 天。外部授权、采购、Cloudflare 账户接入、真实环境排错和历史源码缺失均可能改变关键路径。

推荐以可验收关口排期而非一次承诺全集：

1. 对账与范围确认：完成旧站/权利/数据模型基线。
2. 文本闭环实现：只完成 P0，并进行小范围试点和发布验收。
3. 需求驱动扩展：从 P1 中选择 OCR、影音或教学路线，不同时全部开工。
4. 研究型扩展：P2 须有实际效果和资源依据后再立项。

## MVP 明确舍弃

不做全球全量下载承诺、不采集未授权现代书籍与影音、不训练专用大模型、不复制老师声纹、不做自动证悟判定、不构建完整社交/直播/支付/捐赠系统、不将巨型知识图谱或全部语种设为首发前置。Stream 不进入任何阶段。

## 条目

每项依赖只列直接前置；交付和验收均为目标，完成时必须附实际版本、测试和证据，不能以脚本完成代替真实验收。
